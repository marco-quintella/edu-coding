O **Dockerfile** é a receita da imagem — e `docker build` transforma a receita em imagem executável. Nesta lição você escreve Dockerfiles de verdade e constrói/roda suas próprias imagens no sandbox.

> **Por que importa?** Todo deploy moderno começa num Dockerfile. FROM, CMD, ENV, WORKDIR são o vocabulário que você usa para empacotar QUALQUER app.

## O Dockerfile mínimo

```dockerfile
FROM alpine            # imagem base
CMD ["echo", "app rodando"]   # comando ao rodar o container
```

```python
# Construir a imagem (a partir da pasta do Dockerfile)
docker build -q -t meu-app /tmp/app
# Rodar
docker run --rm meu-app   # → app rodando
```

- **FROM**: a base (tudo começa de uma imagem existente)
- **CMD**: o comando padrão quando o container roda
- **-t meu-app**: nome/tag da imagem

## As instruções essenciais

| Instrução | O que faz |
|---|---|
| `FROM` | imagem base |
| `RUN` | executa comando DURANTE o build |
| `WORKDIR` | diretório de trabalho dentro do container |
| `COPY` | copia arquivos do host para a imagem |
| `ENV` | variável de ambiente |
| `CMD` | comando padrão ao rodar |

## Dockerfile com WORKDIR e RUN

```dockerfile
FROM alpine
WORKDIR /app
RUN echo 'construido' > /app/arquivo.txt
CMD cat /app/arquivo.txt
```

O `RUN` roda **durante o build**; o `CMD` quando o container roda.

## ENV — configurando o app

```dockerfile
FROM alpine
ENV APP_NOME=meu-app
CMD echo "App: $APP_NOME"
```

## Resumo

- **Dockerfile** = receita · **docker build** = cozinha a imagem
- **FROM**: base · **RUN**: durante o build · **CMD**: ao rodar
- **WORKDIR**: diretório de trabalho · **ENV**: variável de ambiente
- **-t nome**: tag da imagem
- Deploy moderno começa no Dockerfile
