APIs reais têm **recursos identificados por id**: `/usuarios/2`, `/produtos/3`. O FastAPI captura esses valores com **path parameters** tipados — e valida o tipo automaticamente. Nesta lição você constrói uma API com rotas dinâmicas e 404.

> **Por que importa?** "Buscar o recurso X pelo id" é a operação #1 de qualquer API. E o 404 correto é o que o frontend usa para tratar "não encontrado".

## Path parameter

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()

@app.get("/usuarios/{usuario_id}")
def buscar(usuario_id: int):
    usuarios = {1: "Ana", 2: "Bob"}
    if usuario_id not in usuarios:
        return {"erro": "usuario nao existe"}
    return {"id": usuario_id, "nome": usuarios[usuario_id]}

client = TestClient(app)
r = client.get("/usuarios/2")
print(r.json())   # {'id': 2, 'nome': 'Bob'}
```

`{usuario_id}` captura o valor da URL; `: int` tipa e valida.

## Validação automática (422)

```python
r = client.get("/usuarios/abc")   # "abc" não é int
# FastAPI devolve 422 — recusa ANTES de chamar a função
```

O type hint `int` faz o FastAPI validar a entrada — sem código extra.

## 404 para não encontrado

```python
if usuario_id not in usuarios:
    return {"erro": "usuario nao existe"}   # 200 com erro
# PROFISSIONAL: raise HTTPException(404, detail="...")
```

**Bônus profissional:** `raise HTTPException(status_code=404)` devolve 404 de verdade.

## Resumo

- **{param}**: path parameter · **: int** valida o tipo
- **422**: tipo inválido (recusado antes da função)
- **404**: recurso não existe (HTTPException ou dict de erro)
- TestClient testa rotas dinâmicas como requests reais
- FastAPI valida com type hints — zero código extra
