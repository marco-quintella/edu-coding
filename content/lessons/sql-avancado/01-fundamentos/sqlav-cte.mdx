**CTEs** (`WITH`) nomeiam consultas intermediárias — transformando SQL complexo em blocos legíveis. Em vez de subquery aninhada ilegível, você cria `WITH totais AS (...)` e usa `totais` como se fosse tabela.

> **Por que importa?** Consultas de produção têm 5+ passos. CTE é como times profissionais organizam SQL — e a pergunta "WITH vs subquery" aparece em entrevistas de dados.

## A estrutura

```sql
WITH totais AS (
    SELECT cliente, SUM(total) AS soma
    FROM pedidos
    GROUP BY cliente
)
SELECT cliente FROM totais WHERE soma > 300
```

1. `WITH totais AS (...)` — **nomeia** a consulta intermediária
2. A query principal usa `totais` como tabela
3. A CTE **não é tabela física** — existe só durante a query

## Por que CTE?

```sql
-- SEM CTE: subquery aninhada (fica ilegível com mais passos)
SELECT cliente FROM (
    SELECT cliente, SUM(total) AS soma FROM pedidos GROUP BY cliente
) WHERE soma > 300

-- COM CTE: blocos nomeados (legível e reutilizável)
WITH totais AS (
    SELECT cliente, SUM(total) AS soma FROM pedidos GROUP BY cliente
)
SELECT cliente FROM totais WHERE soma > 300
```

## Contagem com CTE

```sql
WITH contagem AS (
    SELECT cliente, COUNT(*) AS qtd FROM pedidos GROUP BY cliente
)
SELECT cliente, qtd FROM contagem ORDER BY qtd DESC
```

## Resumo

- **CTE**: `WITH nome AS (SELECT ...)` — bloco nomeado reutilizável
- **Não é tabela física** — existe só durante a query
- Legibilidade: blocos em vez de subqueries aninhadas
- **COUNT/SUM/AVG** dentro da CTE + filtro fora
- CTE = SQL profissional legível
