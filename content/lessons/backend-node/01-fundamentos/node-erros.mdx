Backend real lida com **entrada do cliente**: corpo de POST, query strings e erros. Nesta lição você domina o que falta para uma API completa: ler o corpo, parsear JSON, padronizar erros e usar parâmetros de query.

> **Por que importa?** O frontend manda dados no corpo (POST), filtros na query (`?a=10`) — e o backend precisa responder erros de forma consistente para o app tratar.

## Lendo o corpo (POST)

```js
const server = http.createServer((req, res) => {
  if (req.url === "/echo" && req.method === "POST") {
    let corpo = "";
    req.on("data", (chunk) => (corpo += chunk));   // pedaços chegam
    req.on("end", () => {
      const dados = JSON.parse(corpo);             // string → objeto
      res.writeHead(200, { "Content-Type": "application/json" });
      res.end(JSON.stringify({ recebido: dados.nome }));
    });
  }
});
```

O corpo chega **em pedaços** (eventos `data`); juntamos tudo e só no `end` temos o corpo completo.

## Erros padronizados

```js
// Sempre JSON, sempre com o campo "erro"
res.writeHead(404, { "Content-Type": "application/json" });
res.end(JSON.stringify({ erro: "nao encontrado" }));
```

**Regra:** frontend trata `{ erro: "..." }` — consistência é o que importa.

## Query strings

```js
// /soma?a=10&b=5
const m = req.url.match(/^\/soma\?a=(\d+)&b=(\d+)$/);
if (m) {
  const resultado = Number(m[1]) + Number(m[2]);
  res.end(JSON.stringify({ resultado }));
}
```

A query string são **parâmetros extras** depois do `?` — separados por `&`.

## Resumo

- **Corpo**: `req.on('data')` acumula · `req.on('end')` processa · `JSON.parse`
- **Erro padronizado**: `{ erro: "..." }` + status certo
- **Query string**: parâmetros após `?`, separados por `&`
- **500** = erro interno · **400** = requisição inválida
- Consistência de erros = frontend feliz
