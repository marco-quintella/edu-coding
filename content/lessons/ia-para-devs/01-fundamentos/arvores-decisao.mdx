Uma árvore de decisão é o modelo de ML **mais próximo do raciocínio humano**: uma sequência de perguntas sim/não sobre os dados, cada resposta levando a uma pergunta mais específica, até chegar a uma decisão. É o que você faz ao escolher um restaurante ("está aberto? → tem fila? → quanto custa?") — só que automatizado e otimizado estatisticamente.

## Estrutura

```python
                [petal_length < 2.45?]
                /                  \
              yes                   no
              /                      \
        [setosa]            [petal_width < 1.75?]
                              /              \
                            yes               no
                            /                  \
                     [versicolor]           [virginica]
```

- **Raiz**: primeiro teste, divide o dataset inteiro
- **Nós internos**: testes sobre atributos
- **Folhas**: decisão final (classe ou valor)
- **Arestas**: resultados do teste (yes/no)

> **Intuição:** a árvore é um "jogo de 20 perguntas" aprendido dos dados. O algoritmo decide **qual pergunta fazer primeiro** — e isso é o coração do modelo.

## A pergunta central: qual teste fazer?

A raiz da árvore faz o teste que **mais separa as classes**. Mas como medir "quão bem um teste separa"?

A resposta é a **impureza** — o quanto um grupo é "misturado". Duas métricas:

- **Gini**: `1 - Σ pᵢ²` — probabilidade de classificar errado um item escolhido aleatoriamente
- **Entropia**: `-Σ pᵢ·log₂(pᵢ)` — quantidade de "informação" necessária para identificar a classe

Grupo com uma classe só → impureza 0 (perfeito). Grupo com 50/50 → impureza máxima.

O algoritmo testa **todos os atributos × todos os thresholds possíveis**, calcula a impureza resultante de cada divisão, e escolhe a que mais **reduz** a impureza (o maior "ganho de informação").

```python
# Exemplo: como o Gini é calculado num nó
def gini(proporcoes):
    return 1 - sum(p**2 for p in proporcoes)

# Nó puro (todos setosa) -> gini 0
print(gini([1.0, 0.0, 0.0]))        # 0.0
# Nó 50/50 entre 2 classes -> gini 0.5
print(gini([0.5, 0.5, 0.0]))        # 0.5
# Nó com 3 classes equilibradas -> gini ~0.67
print(gini([1/3, 1/3, 1/3]))        # 0.667
```

## Parâmetros que controlam overfitting

- `max_depth`: profundidade máxima. Maior = mais overfitting
- `min_samples_split`: mínimo de amostras para dividir um nó. **Maior = árvore menor = menos overfitting**
- `min_samples_leaf`: mínimo de amostras numa folha. Similar
- `criterion`: `gini` (default) ou `entropy`

## Por que ninguém usa árvore "pura" em produção

Uma árvore sozinha é fraca: instável e overfitta. Mas **muitas árvores juntas** (ensemble) são fortíssimas:

- **Random Forest**: treina N árvores em amostras aleatórias dos dados + atributos aleatórios, e vota. Reduz a instabilidade e o overfitting
- **Gradient Boosting**: treina árvores em sequência, cada uma corrigindo os erros da anterior (é o que o XGBoost/LightGBM fazem — os modelos dominantes em tabelas)

Por isso a árvore de decisão é o **átomo** dos modelos mais usados em dados tabulares do mundo real.
