Dois algoritmos clássicos de classificação que operam em princípios opostos: o KNN é **baseado em instâncias** (lazy learner — não aprende nada no treino), o SVM é **baseado em função** (eager learner — constrói um modelo no treino). Entender os dois é entender os dois extremos do espectro: "memorizar tudo" vs "extrair o essencial".

## KNN — K-Nearest Neighbors

O KNN classifica um novo ponto olhando os **K vizinhos mais próximos** no espaço de features. A classe é a **majoritária** entre esses K.

> **Intuição:** o KNN é a "lei da vizinhança". Se 4 dos 5 apartamentos mais próximos do seu são de 2 quartos, o seu provavelmente é de 2 quartos. Não existe "modelo" — a decisão é tomada na hora, olhando ao redor.

### Por que "lazy"?

O KNN **não treina nada**: ele guarda todos os dados e só calcula distâncias na hora de prever. Isso tem consequências profundas:

- **Treino instantâneo** (só copia os dados)
- **Predição lenta** (precisa calcular a distância até todos os pontos — O(N) por previsão)
- **Memória alta** (guarda o dataset inteiro em produção)

A pergunta "qual distância?" importa: euclidiana (padrão), manhattan, minkowski. E o valor de `K` é o botão mais importante.

### Parâmetros

- `n_neighbors`: K. K=1 overfitta, K=N underfitta. Comece com `sqrt(N)`
- `metric`: distância (euclidiana default, manhattan, minkowski)
- `weights`: `uniform` ou `distance` (vizinhos mais próximos pesam mais)

## O problema da fronteira irregular

O KNN brilha quando a fronteira entre classes é **irregular** — curvas, bolsões, formas estranhas. Nesses casos, um modelo "geométrico" (como a reta do SVM linear) falha.

## SVM — Support Vector Machine

O SVM encontra o **hiperplano** que separe as classes com a **maior margem** possível. Os pontos mais próximos do hiperplano são os **support vectors** — e são os únicos que importam.

> **Intuição:** imagine duas classes como dois grupos de torcedores num estádio, e você precisa desenhar a linha que os separa. A melhor linha é a que fica **o mais longe possível dos dois grupos** — não a que passa raspando. Os torcedores mais próximos da linha (os que definem onde ela pode ir) são os support vectors.

### Por que "eager"?

O SVM treina de verdade: resolve um problema de otimização para achar o hiperplano de margem máxima. O resultado é um modelo **compacto** — só os support vectors importam (24 de 105 no Iris!). O resto dos dados pode ser descartado.

## Truque do kernel

Quando os dados não são linearmente separáveis, o SVM usa o **kernel trick**: mapeia os dados para um espaço de maior dimensão onde uma separação linear é possível — **sem calcular o mapeamento explicitamente** (isso é o "truque": a função de kernel calcula o produto interno direto).

Kernels comuns:

- `linear`: pra dados linearmente separáveis
- `rbf` (default): gaussiano, funciona bem na maioria dos casos
- `poly`: polinomial

## Comparação direta

| | KNN | SVM |
|---|---|---|
| Treinamento | Instantâneo | Pode demorar |
| Predição | Lenta (busca K vizinhos) | Rápida |
| Memória | Alto (guarda todos os dados) | Baixo (só support vectors) |
| Interpretabilidade | Média | Baixa |
| Escalabilidade | Ruim com N grande | Boa |

## Quando usar cada um

- **KNN**: datasets pequenos/médios, fronteira irregular, quando você precisa de explicabilidade (mostrar os vizinhos)
- **SVM**: dados de tamanho médio em alta dimensão, fronteira suave, robustez (menos overfitting que árvores)
- **Na prática**: nenhum dos dois domina produção hoje — para tabelas usa-se Gradient Boosting/Random Forest; para não-estruturados, redes neurais. Mas entender KNN e SVM é entender **distância** e **margem** — os dois conceitos que sustentam os algoritmos modernos.
