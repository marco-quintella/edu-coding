Um **prompt** é a instrução que você dá ao modelo. A qualidade da resposta depende quase inteiramente da qualidade do prompt — e em produção, cada prompt ruim custa **tokens, latência e retrabalho**. Este guia cobre as técnicas essenciais, com exercícios que você roda no sandbox.

## Os 4 pilares de um bom prompt

1. **Instrução clara** — o que exatamente o modelo deve fazer (comece com verbo)
2. **Contexto** — informações que o modelo precisa saber
3. **Exemplos** — formato e tom esperados (few-shot)
4. **Formato de saída** — estrutura esperada (JSON, lista, markdown)

> **Intuição:** o prompt é a "interface" do seu sistema com o modelo. Um bom prompt é como uma boa API: contrato claro, entradas bem definidas, saída previsível. Um prompt vago é uma API sem documentação — o retorno é sorte.

## Exercício 1: templates de prompt

Prompts reutilizáveis usam **templates** com placeholders — o mesmo padrão do seu código muda só o contexto. Rode e veja como um template vira um prompt completo:

**Pergunta-chave:** por que definir o formato de saída explicitamente? (Resposta: sem ele, o modelo inventa estrutura — às vezes texto, às vezes lista, às vezes JSON com chaves diferentes. Em produção, isso quebra o parser e custa dinheiro. Formato explícito = pipeline previsível.)

## Exercício 2: parsing de saída estruturada

O formato de saída só vale se você **consegue parsear** o que o modelo retorna. O padrão de produção: prompt pede JSON → seu código faz `json.loads` → pipeline continua.

## Técnicas essenciais

### 1. Role prompting

> "Você é um engenheiro de ML sênior. Revise este código e aponte 3 riscos."

O papel define o viés e o nível técnico da resposta.

### 2. Few-shot

Mostrar 2-3 exemplos do formato desejado antes da pergunta real. Funciona como "demonstração".

### 3. Delimitadores

Use `"""`, `###` ou `<tag>` para separar instrução de conteúdo:

```python
Resuma o texto entre <texto>...</texto>:
<texto>...</texto>
```

### 4. Saída estruturada

> "Responda em JSON: `{"sentimento": "positivo|negativo", "confianca": 0-1}`"

### 5. Prompt negativo

> "Não mencione limitações a menos que sejam críticas."

## Checklist de otimização

- [ ] Instrução começa com verbo (resuma, classifique, gere, converta)
- [ ] Formato de saída explícito
- [ ] Exemplos quando o formato é incomum
- [ ] Contexto suficiente para a tarefa
- [ ] Sem ambiguidade ("talvez", "pode ser")
- [ ] Testado com 2-3 variações

## Erros comuns

- **Vago**: "faça um texto sobre IA" → "escreva um parágrafo de 100 palavras explicando atenção em transformers para um dev junior"
- **Sem formato**: modelo inventa a estrutura → defina JSON/lista/tabela
- **Contexto demais**: confunde o modelo → inclua só o necessário
- **Prompt injection**: nunca concatene input do usuário sem sanitizar

## Iteração é a regra

O primeiro prompt raramente é o melhor. Escreva, teste, meça, ajuste — prompt engineering é um loop de iteração, não um one-shot.
