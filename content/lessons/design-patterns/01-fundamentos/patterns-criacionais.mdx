**Padrões criacionais** resolvem "como criar objetos?" — **Singleton** garante UMA instância (config global), **Factory** cria o tipo certo sem expor a lógica (pix vs cartão). São os primeiros padrões que todo dev aprende.

> **Por que importa?** "Por que a config aparece diferente em cada módulo?" → falta de Singleton. "Por que esse if de tipo está em 10 lugares?" → falta de Factory.

## Singleton — uma única instância

```python
class Config:
    _instancia = None

    def __new__(cls):
        if cls._instancia is None:
            cls._instancia = super().__new__(cls)
            cls._instancia.host = "localhost"
        return cls._instancia

c1 = Config()
c2 = Config()
c1 is c2   # True — MESMA instância
```

O `__new__` guarda a instância na classe: a primeira chamada cria, as demais **reutilizam**.

## Factory — cria o tipo certo

```python
class Pagamento:
    def __init__(self, tipo):
        self.tipo = tipo

def criar_pagamento(tipo):
    if tipo == "pix":
        return Pagamento("pix")
    elif tipo == "cartao":
        return Pagamento("cartao")
    return Pagamento("desconhecido")

criar_pagamento("pix")      # Pagamento(pix)
criar_pagamento("cartao")   # Pagamento(cartao)
```

A lógica "qual tipo criar" fica **num lugar só** — o chamador não precisa de ifs.

## Quando usar?

| Padrão | Use quando |
|---|---|
| Singleton | Uma fonte de verdade (config, logger, pool) |
| Factory | O tipo depende de condição (forma de pagamento, conexão) |

- **Singleton**: `__new__` guarda e reutiliza a instância
- **Factory**: função cria o tipo certo — ifs num lugar só
- Singleton = config/logger · Factory = tipos por condição
