APIs **falham** — rede cai, servidor responde 500, recurso não existe. Um cliente profissional **trata esses erros** em vez de quebrar. Nesta lição você constrói um cliente resiliente: captura `HTTPError` (erros HTTP) e `URLError` (falhas de rede), com timeout e retry.

> **Por que importa?** O código que ignora erros de API é o que derruba o app em produção às 3h da manhã. Tratar erros é o que separa script de engenharia.

## O problema

```python
from urllib.request import urlopen

dados = json.loads(urlopen("https://api.exemplo.com/inexistente").read())
# ↑ HTTPError 404 — o programa QUEBRA aqui
```

Sem tratamento, qualquer falha da API derruba o programa inteiro.

## O cliente resiliente

```python
import json
from urllib.request import urlopen
from urllib.error import HTTPError, URLError

def get_json(url):
    try:
        with urlopen(url, timeout=10) as resp:   # timeout: nunca travar
            return resp.status, json.loads(resp.read())
    except HTTPError as e:
        return e.code, {"erro": f"HTTP {e.code}"}   # 404, 500...
    except URLError:
        return 0, {"erro": "rede indisponivel"}     # DNS, conexão

status, dados = get_json(url)
```

- **timeout=10**: se a API não responder em 10s, desiste (nunca trava)
- **HTTPError**: erros com código (404, 500) — o `e.code` tem o número
- **URLError**: falhas de rede (DNS, conexão recusada)

## Retry: quando vale tentar de novo

```python
def get_json_com_retry(url, tentativas=3):
    for tentativa in range(tentativas):
        try:
            with urlopen(url, timeout=10) as resp:
                return resp.status, json.loads(resp.read())
        except Exception:
            if tentativa == tentativas - 1:
                return 0, {"erro": "falhou"}
    return 0, {"erro": "falhou"}
```

Erros transitórios (rede instável, 500) às vezes somem na segunda tentativa.

## Resumo

- **timeout**: nunca travar esperando API morta
- **HTTPError**: erro HTTP com código (e.code) — 404, 500...
- **URLError**: falha de rede (DNS, conexão)
- **Retry**: tentar de novo em erros transitórios
- Cliente resiliente = app que não quebra às 3h da manhã
